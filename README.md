# 하루 — 둘이 같이 쓰는 to-do

할 일만 보면 되는 to-do 앱. 월간 달력은 어느 화면에서도 사라지지 않지만,
일정을 적는 곳이 아니라 **지금 어디쯤 와 있는지 보는 지도**로만 쓴다.
혜인과 민우가 **같은 공간을 함께 쓰되, 체크는 각자 자기 것만** 한다.

웹과 앱(설치형 PWA) 모두 같은 코드로 동작하고, 데이터는 서버에 저장된다.

```
npm install
cp .env.example .env      # HARU_SECRET 만 채우면 됩니다
npm run build
npm start                 # http://localhost:4000
```

---

## 세 갈래

| 갈래 | 색 | 누가 쓰나 |
|------|-----|-----------|
| **나** | 라일락 `#A281EE` | 내 개인 일정 — 나만 체크 |
| **상대** | 스카이 `#3E9DE8` | 상대 개인 일정 — 상대가 직접 적고 체크. 나는 **보기만** |
| **업무** | 버밀리언 `#F5503C` | **내 업무. 상대 화면에는 아예 내려가지 않는다** |

갈래는 사람 이름이 아니라 **보는 사람 기준의 자리**로 정의된다.
혜인이 열면 왼쪽이 혜인, 민우가 열면 왼쪽이 민우다. 달력 막대 순서도 같이 뒤집힌다.

```
내 갈래   = lane 'personal' + owner === 나
상대 갈래 = lane 'personal' + owner === 상대
업무      = lane 'work'     + owner === 나
```

### 공유 규칙 셋

1. **체크는 자기 것만** — 상대 갈래 항목은 체크박스가 아니라 **점**으로 그려진다.
   흐린 체크박스는 "언젠가 눌릴 것"처럼 보이므로 모양 자체를 바꿨다.
2. **같이 하는 일은 한 번만** — `같이` 배지가 붙은 항목은 둘 다 체크할 수 있고,
   한 명이 체크하면 양쪽에서 완료된다.
3. **재촉하지 않는다** — 독촉 알림도, 콕 찌르기도, 스트릭도 없다.

## 시간 개념이 없다

시각도, `아침·낮·저녁` 같은 구간도 묻지 않는다. 데이터 모델에 `time` 필드가 아예 없다.
순서가 신경 쓰이면 목록에서 위로 끌어 올리면 된다.

| 상황 | 흔한 앱 | 여기서는 |
|------|---------|----------|
| 할 일 적을 때 | 날짜·시각·소요시간·우선순위를 묻는다 | **제목만.** 날짜도 선택 |
| 어제 못 끝냈을 때 | 빨간 "지연"이 쌓인다 | 맨 위 한 줄 + `오늘로 옮기기` |
| 언제 할지 모를 때 | 일단 오늘 날짜가 붙는다 | **"언젠가"** 서랍. 알림도 독촉도 없음 |
| 다 못 한 하루의 끝 | 달성률 20% | 퍼센트를 쓰지 않는다. 개수로만 |

## 달력 칸 읽는 법

칸 안에 글자는 날짜 숫자뿐이다. 그날의 양은 얇은 막대 세 줄로만 보여준다.

| 표시 | 뜻 |
|------|-----|
| 막대 길이 8 / 14 / 20px | 1–2개 / 3–4개 / 5개 이상 |
| 첫째 줄 · 둘째 줄 · 셋째 줄 | 나 · 상대 · 업무 (순서 고정) |
| **빨강이 길면** | 일에 잡아먹힌 날 |
| **빨강이 없으면** | 둘 다 여유 있는 날 |
| 회색 막대 | 다 끝냈거나 지나간 날 |

## 구조

```
server/          Express 5 + node:sqlite (Node 22 내장) — API 와 정적 파일을 한 프로세스에서
  src/db.ts        스키마 + 마이그레이션 (user_version 기반)
  src/auth.ts      scrypt 해시, HMAC 서명 httpOnly 쿠키 세션
  src/todos.ts     조회·쓰기 + 갈래 계산과 권한 판정
  src/events.ts    SSE 허브 — 한쪽이 바꾸면 다른 쪽 화면이 스스로 갱신
  src/routes/      auth · space · todos
  test/            node:test 통합 테스트 15개

web/             React 19 + Vite 8 + TypeScript
  src/lib/         api · store(Context) · 날짜 계산
  src/components/  달력 패널 · 하루/이번 주/언젠가 · 로그인 · 우리
  src/styles/      디자인 토큰 + 화면 스타일 (라이트/다크)
  public/          manifest · 아이콘 · 서비스워커

docs/design/     설계 문서와 화면 시안 (v0.1 → v0.6)
```

**네이티브 의존성이 없다.** SQLite 는 Node 22 내장 `node:sqlite` 를 쓰고,
서버 TypeScript 는 Node 의 타입 스트리핑으로 빌드 없이 그대로 돈다.

## 환경변수

`.env.example` 참고. 운영에서 필요한 건 **`HARU_SECRET` 하나**다.

| 변수 | 기본값 | 설명 |
|------|--------|------|
| `HARU_SECRET` | (개발 시 임시 생성) | 세션 쿠키 서명 키. `NODE_ENV=production` 이면 **필수** |
| `HARU_DB_PATH` | `./data/haru.db` | SQLite 파일. 컨테이너면 볼륨 경로로 |
| `PORT` / `HOST` | `4000` / `0.0.0.0` | |
| `NODE_ENV` | — | `production` 이면 쿠키가 `secure` 로 나간다 (HTTPS 필요) |

## 처음 쓰기

1. 한 사람이 가입한다 → 공간이 만들어지고 **초대 코드**가 나온다
2. `우리` 화면에서 코드를 복사해 상대에게 준다
3. 상대가 가입할 때 그 코드를 넣으면 같은 공간을 쓰게 된다
   (이미 가입했다면 `우리 → 합류`. 그때까지 적은 할 일은 그대로 따라온다)

한 공간에는 **두 사람까지만** 들어갈 수 있다.

## 앱으로 설치하기

빌드된 앱은 PWA다. 모바일 브라우저에서 열고 **홈 화면에 추가**하면 주소창 없이 앱처럼 뜬다.

서비스워커는 **앱 껍데기만** 캐시한다. 할 일 데이터는 캐시하지 않는다 —
둘이 같이 쓰는 앱에서 오래된 목록을 보여주는 건 안 보여주는 것보다 나쁘다.

> iOS 에서 홈 화면 추가는 HTTPS 에서만 동작한다. 로컬 테스트는 브라우저로 충분하다.

## 실시간 반영

상대가 무언가 바꾸면 SSE(`/api/events`)로 신호가 오고 화면이 스스로 다시 불러온다.
신호에는 **변경 내용이 실리지 않는다** — 각자 자기 권한으로 다시 조회하므로
남에게 보이면 안 되는 업무 항목이 새어 나갈 길이 없다.
탭으로 돌아왔을 때도 한 번 맞춘다.
