원칙

부담을 만들지 않는 네 가지 규칙

01

시간이 아예 없다

시각도, 아침·낮·저녁 같은 구간도 없습니다. 순서가 신경 쓰이면 목록에서 위로 끌어 올리면 됩니다. 그게 전부입니다.

02

달력은 읽는 곳

칸 안에 글씨를 넣지 않습니다. 얇은 막대 두 줄로 그날의 양만 보여줍니다. 빽빽한 날과 한가한 날이 형태로 읽힙니다.

03

못 한 건 그냥 넘어간다

빨간 "지연"이 뜨지 않습니다. 어제 남은 항목은 조용히 위에 모여 오늘로 옮기기 / 나중에 두 버튼만 있습니다.

04

구분은 색 + 위치

개인은 왼쪽·라일락, 업무는 오른쪽·스카이. 색만으로 나누지 않아 색약이거나 화면이 작아도 자리로 구분됩니다.

위·아래

위가 업무, 아래가 개인. 순서가 고정이라 색을 몰라도 구분됩니다.

회색이면

다 끝냈거나 이미 지나간 날. 회색은 신경 쓸 필요 없다는 뜻입니다.

아무것도 없으면

비어 있는 날입니다. 비었다고 뭘 채우라는 표시는 어디에도 뜨지 않습니다.

어제 못 끝냈을 때 빨간 "지연" 배지가 계속 쌓인다 맨 위에 한 줄로 조용히 모아 옮기기 / 나중에 두 버튼
순서를 정하고 싶을 때 시:분을 지정하게 한다 시간 개념이 아예 없다. 목록에서 위로 끌어 올리면 끝
언제 할지 모를 때 일단 오늘 날짜가 붙는다 "언젠가" 서랍에 담긴다. 알림도 독촉도 없음
다 못 한 하루의 끝 달성률 20% 같은 숫자를 보여준다 퍼센트를 쓰지 않는다. "2개 남음"처럼 개수로만
연속 기록 스트릭이 끊기면 불이 꺼진다 스트릭·연속일수 기능 자체를 넣지 않는다

디자인 토큰

색과 글자

맑은 하늘색 바탕에 스카이와 라일락 두 가지. 같은 색을 밝은 값과 짙은 값 두 벌로 나눠, 밝은 쪽은 막대·체크 같은 표시에, 짙은 쪽은 글자에 씁니다 — 화면은 화사하고 글자는 또렷합니다. 경고용 빨강은 팔레트에 없습니다.

형태

선 대신 면

격자선을 지우고 옅은 면과 여백으로 나눕니다. 모서리는 9–10px로 둥글게, 그림자는 거의 없이.

접근성

색 없이도 읽힌다

스카이와 라일락은 둘 다 시원한 계열이라 색만으로는 헷갈릴 수 있습니다. 그래서 개인은 늘 왼쪽·아래 막대, 업무는 늘 오른쪽·위 막대로 자리를 고정했습니다. 터치 영역 44px 이상.

웹 · 앱

화면이 좁아지면

달력은 어느 크기에서도 화면에서 빠지지 않습니다. 형태만 바뀝니다.

논의

이번엔 이것만 정하면 됩니다

  1. 방향이 맞나요? 시간표를 완전히 없애고 달력을 "읽는 지도"로만 쓰는 이 구조가 원하시던 느낌인지 먼저 확인하고 싶습니다.
  2. 달력 칸의 막대 표시 — 지금은 얇은 막대 두 줄입니다. 점 두 개, 혹은 숫자만 남기는 것도 가능합니다. 어느 쪽이 편한가요?
  3. 주간 화면(S2)이 필요한가요? 하루 + 달력만으로 충분하다면 탭을 하나 줄여 더 단순해집니다.
  4. 알림 — 지금 설계엔 독촉 알림이 없습니다. 아침에 한 번 "오늘 3개 있어요" 정도만 둘까요, 아니면 아예 없앨까요?
