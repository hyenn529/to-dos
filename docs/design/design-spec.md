# 하루(가칭) — 화면 설계서 v0.4

캘린더가 늘 곁에 있는 개인·업무 to-do 서비스. 웹과 앱 모두 지원.
**논의용 초안이며, 구현 코드는 아직 없습니다.**

시각 시안: [`screens.html`](./screens.html)

## 0. v0.1 → v0.2 — 방향 전환

v0.1은 일반적인 캘린더 앱(시간 격자 + 일정 블록) 구조였고,
**시간 단위 관리처럼 느껴져 부담스럽다**는 피드백을 받았다.
부담의 원인은 대부분 "시간을 정하라고 요구하는" 요소였으므로 그것부터 제거했다.

| 뺀 것 | 남긴 것 |
|-------|---------|
| 주간 시간표(08–20시 격자) | 체크리스트 — **이것이 본체** |
| 일정 블록 · 시작/종료 시각 | 개인 · 업무 두 갈래 구분 |
| 현재 시각 라인 | **항상 떠 있는 월간 달력** |
| 소요 시간 예측 · 드래그 배치 | 날짜별 · 주간 훑어보기 |
| 지연 경고 배지 | 순서가 필요하면 손으로 끌어 옮기기 |
| 달력 칸 안의 일정 이름 | 날짜 없이 담아두는 "언젠가" |
| 아침 · 낮 · 저녁 구간 *(v0.3에서 제거)* | |

**핵심 구조**: 화면은 `왼쪽 = 달력(읽기용) / 오른쪽 = 할 일(작업용)`.
달력은 일정을 적는 곳이 아니라 **지금 어디쯤 와 있는지 보는 지도**다.

## 1. 설계 원칙

| # | 원칙 | 의미 |
|---|------|------|
| 1 | **시간이 아예 없다** | 시각도, 아침·낮·저녁 같은 구간도 없다. 순서가 신경 쓰이면 목록에서 위로 끌어 올리면 된다 |
| 2 | **달력은 읽는 곳** | 칸 안에 글자를 넣지 않는다. 얇은 막대 두 줄로 그날의 *양*만 표시 |
| 3 | **못 한 건 그냥 넘어간다** | 빨간 "지연" 배지 없음. 어제 남은 항목은 맨 위에 조용히 모아 `오늘로 옮기기 / 나중에` 두 버튼만 |
| 4 | **구분은 색 + 위치** | 개인=왼쪽·아래막대·라일락, 업무=오른쪽·위막대·스카이. 두 색이 같은 시원한 계열이라 **자리 고정이 특히 중요**하다 |

## 2. 정보 구조

### 웹 — 2단
- **왼쪽 (352px 고정)** — 월간 달력 · 범례 · 남은 개수 요약. **어느 화면에서도 그대로**
- **오른쪽** — `하루` / `이번 주` / `언젠가` 세 가지 중 하나

### 앱 — 4탭
`하루` / `이번 주` / `언젠가` / `나`
달력은 탭이 아니라 **상단 고정 영역**이다. 스크롤해도 사라지지 않고, 위로 쓸어올리면 그 주 한 줄로 줄어들 뿐이다.

### 데이터 모델 (초안)

```
Todo {
  id
  lane     : 개인 | 업무           // 최상위 속성
  title                            // 필수 — 이것만 있으면 저장됨
  date?                            // 없으면 "언젠가" 서랍
  order                            // 같은 날 안에서의 순서 (손으로 끌어서 변경)
  done, doneAt?
  note?, tags[]
  subs[]   : { title, done }       // 하위 체크
  repeat?
  carriedFrom?                     // 이월 표시 "어제에서"
}
```

시각(`time`), 시간 구간(`part`), 소요시간(`estimate`), 우선순위(`priority`),
지연(`overdue`) 필드는 **의도적으로 없다.** 하루 안의 순서는 `order` 하나로 충분하다.

## 3. 화면별 사양

### S1. 기본 화면 (웹) — `하루`

**왼쪽 달력 패널**
- 6주 × 7일, 칸 높이 52px, 칸 안은 **날짜 숫자 + 얇은 막대 두 줄**뿐
- 오늘 = 짙은 채움, 선택한 날 = 얇은 테두리, 일요일·공휴일 = 바이올렛 숫자
- 아래에 범례, 그 아래 `개인 n 남음 / 업무 n 남음 / 언젠가 n`

**오른쪽 본문**
- 상단: 날짜 + `하루 / 이번 주 / 언젠가` 전환 + `＋ 추가`
- 이월 안내: "어제 못 한 일이 2개 있어요" → `오늘로 옮기기` `나중에`
- **개인 · 업무 좌우 2단**. 각 레인 헤더에 `n 남음 · n 완료` (퍼센트 아님)
- 완료 항목은 접히고, 배경 없이 취소선 + 흐린 글자로만 남음
- 하위 체크(예: 여행 준비 3개)는 카드 안에 인라인

### S2. 이번 주 (웹)

- **달력 패널은 그대로.** 선택한 주가 달력에서 테두리로 표시됨
- 오른쪽만 7개 컬럼으로 — **시간축 없음, 그냥 목록 7개**
- 오늘 컬럼만 테두리로 강조, 주말 컬럼은 배경 없이 옅게
- 컬럼 사이 드래그는 **날짜만** 바꾼다 (시각 개념 없음)
- 상단 요약: `14개 남음` `이번 주 8개 완료`

> 시간 격자가 없으니 "비어 있는 시간"이 보이지 않고, 따라서 채워야 한다는 압박도 생기지 않는다.

### S3. 모바일 앱

| 화면 | 구성 |
|------|------|
| 기본 | 상단 고정 달력(한 달) + 아래 목록만 스크롤. 날짜 탭하면 아래만 교체 |
| 달력 접기 | 위로 쓸어올리면 그 주 **한 줄**로 축소. 완전히 사라지지 않음 |
| 적기 | FAB → 제목만 입력. 개인/업무 한 번 누르고 `오늘·내일·이번 주·언젠가` 중 선택(안 골라도 됨) |

> 시간 입력 UI는 어디에도 없다. 목록 안에서 길게 눌러 끌면 순서만 바뀐다.

## 4. 달력 칸 읽는 법

| 표시 | 뜻 |
|------|-----|
| 막대 길이 8px / 14px / 20px | 1–2개 / 3–4개 / 5개 이상 |
| 위쪽 막대 | 업무 (스카이) |
| 아래쪽 막대 | 개인 (라일락) |
| 회색 막대 | 다 끝냈거나 지나간 날 — **신경 쓸 필요 없음** |
| 아무것도 없음 | 비어 있는 날. 채우라는 표시는 뜨지 않음 |

세 단계면 충분하고, 정확한 개수는 눌러서 확인한다.

## 5. 압박을 만들지 않기 위한 규칙

| 상황 | 흔한 앱 | 여기서는 |
|------|---------|----------|
| 할 일 적을 때 | 날짜·시각·소요시간·우선순위를 묻는다 | **제목만.** 개인/업무 한 번 누르고 끝 |
| 어제 못 끝냈을 때 | 빨간 "지연"이 쌓인다 | 맨 위 한 줄 + `옮기기 / 나중에` |
| 순서 정하고 싶을 때 | 시:분을 지정하게 한다 | 시간 개념이 **아예 없다.** 목록에서 위로 끌어 올리면 끝 |
| 언제 할지 모를 때 | 일단 오늘 날짜가 붙는다 | **"언젠가"** 서랍. 알림도 독촉도 없음 |
| 다 못 한 하루의 끝 | 달성률 20% | 퍼센트를 쓰지 않는다. **개수로만** |
| 연속 기록 | 스트릭이 끊기면 불이 꺼진다 | 스트릭 기능 자체를 **넣지 않는다** |

## 6. 디자인 토큰

매일 여는 앱이므로 **밝고 상큼하되 질리지 않는** 쪽으로 잡았다.
채도는 높이고 대신 **색이 칠해지는 면적을 좁게** 쓴다 — 색은 얇은 막대, 체크박스 테두리,
레인 이름에만 들어가고 나머지는 흰 면과 하늘색 여백이다.

**같은 색을 두 벌로 나눠 쓴다.** 밝은 값은 막대·체크·아이콘 같은 *표시*에,
짙은 `-ink` 값은 *글자*에. 그래서 화면은 화사하면서 글자는 또렷하다
(밝은 하늘색을 그대로 글자에 쓰면 흰 배경에서 읽히지 않는다).

| 토큰 | 라이트 | 다크 | 용도 |
|------|--------|------|------|
| `personal` | `#A281EE` 라일락 | `#B79BF7` | 개인 — 막대·체크 |
| `personal-ink` | `#6B3FC4` 바이올렛 | `#C9B4FB` | 개인 — 글자 |
| `work` | `#3E9DE8` 스카이 | `#5FB5F5` | 업무 — 막대·체크 |
| `work-ink` | `#16639F` 오션 | `#8CCBFA` | 업무 — 글자 |
| `ink` | `#1E2A4A` 딥인디고 | `#E6EDFB` | 글자 · 오늘 |
| `paper` | `#E2EDFA` 연한 스카이 | `#0A0F1C` | 바탕 |
| `surface` | `#FFFFFF` | `#141B2E` | 카드 · 본문 면 |
| `faint` | `#A9B4CF` | `#5A6584` | 흐림 · 완료 |

- 검정 대신 **딥인디고**를 글자로 써서 화면 전체가 파랑 계열 안에 머문다
- 달력 패널에는 **스카이 → 라일락 → 흰색**으로 아주 옅게 흐르는 그라데이션을 깔아
  열었을 때 첫인상을 밝게 한다
- **경고용 빨강은 팔레트에 없다.**
- **글자**: 한 가지 산세리프, 굵기로만 구분. v0.1의 고정폭(모노) 숫자를 전부 제거 — 계기판 같던 인상이 사라진다. 달력 숫자만 `tabular-nums`로 정렬
- **형태**: 격자선 대신 옅은 면과 여백. 모서리 9–12px, 막대는 완전히 둥글게, 그림자 거의 없음
- **접근성**: 색 없이도 자리로 구분 / 대비 4.5:1 이상 / 터치 44px 이상

## 7. 화면이 좁아지면

달력은 어느 크기에서도 화면에서 빠지지 않는다. 형태만 바뀐다.

| 폭 | 달력 | 할 일 |
|----|------|-------|
| ≥1200 | 왼쪽 고정 패널 · 한 달 전체 | 개인·업무 좌우 2단 |
| 900–1199 | 왼쪽 고정 · 패널 폭만 축소 | 2단 유지 |
| 600–899 | 상단 고정 · 한 달 전체 | 개인 → 업무 세로 배치 |
| <600 | 상단 고정 · 스크롤 시 그 주 한 줄로 축소 | 세그먼트 전환 후 한 줄 목록 |

## 8. 결정이 필요한 항목

1. **달력 칸 표시** — 얇은 막대 두 줄 / 점 두 개 / 숫자만, 어느 쪽이 편한지
2. **주간 화면(S2)이 필요한지** — 하루 + 달력만으로 충분하면 탭을 하나 줄일 수 있음
3. **알림** — 아침에 한 번 "오늘 3개 있어요" 정도만 둘지, 아예 없앨지

## 9. 설계 이력

| 버전 | 내용 |
|------|------|
| v0.1 | 일반적인 캘린더 앱 구조(주간 시간표 + 일정 블록). *시간 단위 관리처럼 느껴져 폐기* |
| v0.2 | 시간 격자·일정 블록 제거. to-do 중심 + 달력 상주 구조로 전면 재설계 |

| v0.4 | 팔레트를 **하늘색(스카이) · 연보라(라일락)** 로 교체. 표시용/글자용 두 벌 구조 도입 |
