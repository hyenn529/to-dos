# 겹(가칭) — 화면 설계서 v0.1

개인·업무를 함께 관리하는 일정/할 일 서비스. 웹과 앱 모두 지원.
**이 문서는 논의용 초안이며, 구현 코드는 아직 없습니다.**

시각 시안: [`screens.html`](./screens.html)

---

## 1. 문제 정의

- 캘린더를 개인/업무로 **분리**하면 → 두 일정이 부딪히는지 안 보인다.
- 하나로 **합치면** → 무엇이 내 것이고 무엇이 회사 것인지 구분이 사라진다.

→ **하나의 시간축 위에 두 개의 레인(Lane)**을 얹는다. 모든 화면에서 일관되게.

## 2. 설계 원칙

| # | 원칙 | 의미 |
|---|------|------|
| 1 | 구분은 색 + 위치 | 개인/업무를 색으로만 나누지 않는다. 왼쪽 3px 스트라이프, 좌우 분할, 배지까지 이중·삼중 인코딩 |
| 2 | 일정 ≠ 할 일 | 일정은 시간을 *차지*하고, 할 일은 *끝나야* 한다. 같은 날짜축에 그리되 표현을 분리(블록 vs 체크) |
| 3 | 월간에서도 할 일이 보인다 | 월간 캘린더 우측 인스펙터에 선택한 날의 개인/업무 할 일을 항상 노출 |
| 4 | 상태는 형태로 | 지연·마감임박을 빨강으로 칠하면 개인 레인 색과 싸운다. 채운 배지/점선/굵기로 표현 |

## 3. 정보 구조

### 웹 — 3단 레이아웃
- **사이드바** — 뷰 전환(월간/주간/오늘/할 일), 미니 캘린더, 레인 토글, 태그
- **본문** — 월간 / 주간 / 일간 / 할 일 목록
- **인스펙터** — 선택한 날짜 또는 항목의 상세

### 앱 — 4탭
- **오늘**(기본 진입) / **캘린더** / **할 일** / **나**

### 공통 데이터 모델 (초안)

```
Item {
  id
  lane      : 개인 | 업무          // 최상위 속성 — 모든 뷰에서 같은 필터가 작동
  kind      : 일정 | 할일
  title
  start?, end?, allDay             // 일정
  due?, done, priority             // 할 일
  estimate?                        // 소요 시간 (드래그 배치용)
  tags[], repeat?, remind[]
  parentId?                        // 하위 항목
}
```

`lane`이 최상위 속성이라 월간/주간/일간/목록 어디서든 동일한 필터 로직이 재사용된다.

## 4. 화면별 사양

### S1. 월간 캘린더 (웹) — 기본 진입 뷰

- 6주 × 7일 고정 그리드, 셀 높이 86px
- **시간 일정**: 칩으로 최대 3개, 초과분은 `＋n개 더`
- **시간 없는 할 일**: 셀 하단에 레인별 **개수 점**으로만 요약 (그리드 오염 방지)
- **여러 날 일정**: 채운 막대로 연결 표시
- 오늘 = 채운 원, 선택한 날 = 2px 외곽선
- 우측 인스펙터: 날짜 / 레인별 진행률 바 / 업무 목록 / 개인 목록 / 인라인 추가

### S2. 주간 뷰 (웹)

- 상단 **종일·마감** 영역 + 08–20시 시간축(1시간 = 33px)
- 이벤트 블록: 왼쪽 3px 스트라이프로 레인 구분
- 현재 시각 라인(signal 컬러) + 시각 라벨
- **좌측 미배치 트레이**: 시간이 없는 할 일 목록. 시간표로 드래그하면 그 자리에 블록 생성
  - 블록과 할 일은 계속 연결됨 (블록 완료 = 할 일 완료)
  - 드래그 중 점선 고스트로 위치·소요시간 미리보기
- 주간 합계: 레인별 투입 시간(h)

### S3. 오늘 / 일간 (웹)

- **좌우 2단 분할**: 왼쪽 개인, 오른쪽 업무 — 레인 헤더에 2px 밑줄과 `완료/전체` 카운트
- 카드에 하위 항목(체크박스) 인라인 표시
- **완료 항목은 접힘** + 대시 테두리 + 취소선 (완료가 화면을 잡아먹지 않도록)
- 우측 **시간 레일**: 오늘의 시간 일정 미니 타임라인. 빈 구간 클릭 → 일정 생성

### S4. 모바일 앱

| 화면 | 구성 |
|------|------|
| 캘린더 탭 | 점 요약 그리드 + 바텀시트(드래그로 확장), 좌우 스와이프로 월 이동, 상단 전체/개인/업무 세그먼트 |
| 오늘 탭 | 레인별 진행률 2개 + 세그먼트 전환(업무·개인·전체) + 카드 목록 |
| 빠른 추가 | FAB → 한 줄 자연어 입력(`내일 오후 3시 치과`) → 파싱 결과를 칩으로 확인·수정. **레인 선택은 항상 한 번의 탭 안에** |

앱 전용 추가 기능: **홈 위젯 · 푸시 알림 · 오프라인 저장**

## 5. 디자인 토큰

| 토큰 | 라이트 | 다크 | 용도 |
|------|--------|------|------|
| `work` | `#25456F` | `#8AAFE0` | 업무 레인 |
| `personal` | `#A2432D` | `#E1927B` | 개인 레인 |
| `ink` | `#14171D` | `#E7EAEF` | 본문 / 오늘 표시 |
| `signal` | `#A8781E` | `#D6A94C` | 현재 시각 라인 |
| `paper` | `#E7EAEF` | `#0D1015` | 바탕 |
| `line` | `#D2D7DF` | `#2C323C` | 구분선 |

- **타이포**: 본문은 한글 산세리프(Pretendard / Apple SD Gothic Neo / Noto Sans KR),
  시각·날짜·개수·소요시간은 **모노스페이스 + `tabular-nums`**
- **간격**: 4px 배수 그리드. 라운드 3px(밀도 높은 표에서 형태가 흐려지지 않도록)
- **접근성**: 레인은 색+스트라이프+위치 삼중 표시 / 본문 대비 4.5:1 이상 / 터치 타깃 44px / 포커스 링 상시

## 6. 반응형 정책

| 폭 | 월간 | 주간 | 일간 | 추가 |
|----|------|------|------|------|
| ≥1280 | 사이드바 + 그리드 + 인스펙터 | 트레이 + 7일 | 좌우 2단 + 시간 레일 | 모달·인라인 |
| 960–1279 | 인스펙터 슬라이드 | 트레이 접힘 | 2단, 레일 접힘 | 모달 |
| 600–959 | 사이드바 → 드로어 | 3일 뷰 | 2단 유지 | 바텀시트 |
| <600 | 점 요약 + 바텀시트 | 1일 스와이프 | 세그먼트 전환 | FAB → 빠른 추가 |

웹·앱은 하나의 반응형 코드베이스에서 갈라지는 것을 전제로 설계했다.

## 7. 결정이 필요한 항목

1. **레인은 2개 고정인가?** — 2개면 좌우 분할이 성립. 3개 이상이면 분할 대신 그룹 목록으로 바꿔야 함
2. **외부 캘린더 연동 여부** — Google/Outlook 연동 시 읽기전용 외부 일정 표현(빗금 블록)과 충돌 경고 UI 추가 필요
3. **1인용인가, 팀 공유인가** — 공유가 있으면 담당자 아바타·공유 배지·권한 UI가 카드/셀에 들어가야 함. 현재 시안은 1인 전제
4. **주 시작 요일 / 근무 시간대** — 현재 월간=일요일 시작, 주간=월요일 시작, 시간축 08–20시. 설정화 여부
5. **드래그 배치(할 일 → 시간표)** — 가장 매력적이지만 구현 비용 최대. 1차 범위에서 제외 가능
