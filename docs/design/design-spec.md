# 하루(가칭) — 화면 설계서 v0.6

캘린더가 늘 곁에 있는, **혜인과 민우가 같이 쓰는** 세 갈래 to-do 서비스.
웹과 앱 모두 지원. **논의용 초안이며, 구현 코드는 아직 없습니다.**

시각 시안: [`screens.html`](./screens.html)

---

## 0. 세 갈래

| 갈래 | 색 | 성격 |
|------|-----|------|
| **혜인** | 라일락 `#A281EE` | 혜인의 개인 일정. 혜인만 체크 가능, 민우는 볼 수 있음 |
| **민우** | 스카이 `#3E9DE8` | 민우의 개인 일정. 민우만 체크 가능, 혜인은 볼 수 있음 |
| **업무** | 버밀리언 `#F5503C` | 둘 다 사용. 항목마다 아바타, 기본은 `내 것만` 보기 |

사람 둘은 **이웃한 시원한 색**으로 묶고, 업무만 **색상환 반대편 빨강**으로 뺐다.
일이 끼어든 날이 달력에서 즉시 튄다.

> **빨강을 갈래에 쓸 수 있는 이유** — 지연·마감을 색으로 알리는 앱에서는 빨강이 경고에
> 묶여 있다. 이 설계에는 **경고 자체가 없어서** 빨강이 비어 있었다. 그 자리를 업무가 쓴다.

## 1. 공유 규칙

같이 쓰는 앱이 어려워지는 건 대개 "누가 뭘 할 수 있는지"가 흐릿해서다. 규칙은 셋뿐이다.

1. **체크는 자기 것만** — 상대 갈래 항목은 체크박스가 아예 나타나지 않고 **작은 점**으로 보인다.
   흐린 체크박스는 "지금은 안 되지만 언젠가 될 것"처럼 보이므로, 아예 다른 모양으로 바꾼다.
2. **같이 하는 일은 한 번만** — `같이` 배지가 붙은 항목은 둘 다 체크할 수 있고,
   한 명이 체크하면 양쪽에서 완료된다.
3. **이름은 보는 사람 기준** — 민우가 열면 왼쪽 칸이 **민우**가 된다.
   언제나 `자기 갈래 → 상대 → 업무` 순서. 달력 막대 순서도 함께 뒤집힌다.

상대 갈래에 내가 적으면 바로 들어가지 않고 **제안**으로 전달된다.

## 2. 문제 정의와 방향

- 캘린더 앱의 **시간 격자**는 "몇 시에 무엇을 할지" 정하라고 요구해 부담이 된다
- 하지만 **한 달의 흐름**은 계속 보고 싶다

→ 화면을 `왼쪽 = 달력(읽기용) / 오른쪽 = 할 일(작업용)`로 나눈다.
달력은 일정을 적는 곳이 아니라 **지금 어디쯤 와 있는지 보는 지도**다.

## 3. 설계 원칙

| # | 원칙 | 의미 |
|---|------|------|
| 1 | **시간이 아예 없다** | 시각도, 아침·낮·저녁 같은 구간도 없다. 순서가 신경 쓰이면 목록에서 위로 끌어 올린다 |
| 2 | **달력은 읽는 곳** | 칸 안에 글자를 넣지 않는다. 얇은 막대 세 줄로 그날의 *양*만 표시 |
| 3 | **못 한 건 그냥 넘어간다** | 빨간 "지연" 배지 없음. 어제 남은 항목은 맨 위에 조용히 모아 `오늘로 옮기기 / 나중에` |
| 4 | **재촉하지 않는다** | 상대가 안 한 일에 대한 알림이 없다. **독촉 버튼도, 콕 찌르기도 넣지 않는다** |

## 4. 정보 구조

### 웹 — 2단
- **왼쪽 (320px 고정)** — 월간 달력 · 범례 · 갈래별 남은 개수. **어느 화면에서도 그대로**
- **오른쪽** — `하루` / `이번 주` / `언젠가` 세 가지 중 하나

### 앱 — 4탭
`하루` / `이번 주` / `언젠가` / `우리`
달력은 탭이 아니라 **상단 고정 영역**이다. 스크롤해도 사라지지 않고, 위로 쓸어올리면 그 주 한 줄로 줄어들 뿐이다.

### 데이터 모델 (초안)

```
Space {                              // 혜인 + 민우가 공유하는 하나의 공간
  id, members: [User, User]
}

Todo {
  id
  lane      : 혜인 | 민우 | 업무      // 최상위 속성
  owner     : userId                 // 이 항목을 체크할 수 있는 사람
  together  : bool                   // true 면 둘 다 체크 가능, 한 번 체크로 양쪽 완료
  title                              // 필수 — 이것만 있으면 저장됨
  date?                              // 없으면 "언젠가" 서랍
  endDate?                           // 여러 날 항목 (출장 등)
  order                              // 같은 날 안에서의 순서 (손으로 끌어서 변경)
  countable                          // 상대 갈래는 false — 내 완료 집계에서 제외
  proposedBy?                        // 상대가 제안한 항목
  done, doneAt?, doneBy?
  note?, tags[], subs[], repeat?, carriedFrom?
}
```

시각(`time`), 시간 구간(`part`), 소요시간(`estimate`), 우선순위(`priority`),
지연(`overdue`) 필드는 **의도적으로 없다.**

## 5. 화면별 사양

### S1. 기본 화면 (웹) — `하루`

**왼쪽 달력 패널**
- 6주 × 7일, 칸 높이 58px, 칸 안은 **날짜 숫자 + 얇은 막대 세 줄**뿐
- 막대 순서 위→아래: **나 · 상대 · 업무** (보는 사람 기준)
- 상단에 두 사람 아바타 — 지금 누구와 같이 쓰는지 항상 보임
- 오늘 = 짙은 채움, 선택한 날 = 얇은 테두리, 일요일·공휴일 = 바이올렛 숫자

**오른쪽 본문**
- 이월 안내: "어제 못 한 일이 2개 있어요" → `오늘로 옮기기` `나중에`
- **나 · 상대 · 업무 3단**
  - 내 갈래 헤더에 `나` 배지, 상대 갈래 헤더에 `보기만` 배지, 업무에 `내 것만` 토글
  - 상대 갈래 개수는 `n 남음`이 아니라 **`n 건`** (완료를 세지 않으므로)
  - 상대 갈래 하단 추가 버튼은 `＋ 민우에게 제안`
- 완료 항목은 접히고, 배경 없이 취소선 + 흐린 글자로만 남음

### S2. 이번 주 (웹)

- **달력 패널은 그대로.** 선택한 주가 달력에서 테두리로 표시됨
- 오른쪽만 7개 컬럼 — **시간축 없음, 그냥 목록 7개**
- 빨강이 확실히 튀므로 **일이 몰린 날**과 **둘만의 날**이 색만 보고 갈린다
- 컬럼 사이 드래그는 **날짜만** 바꾼다

### S3. 모바일 앱

| 화면 | 구성 |
|------|------|
| 기본 | 상단 고정 달력 + 아래 목록. 목록은 **나 → 상대 → 업무** 순 |
| 갈래 필터 | `전체 · 나 · 상대 · 업무` 칩 |
| 상대 화면 | 같은 데이터인데 **자기 갈래가 왼쪽/맨 위**로 온다. 달력 막대 순서도 뒤집힘 |
| 달력 접기 | 위로 쓸어올리면 그 주 **한 줄**로 축소. 완전히 사라지지 않음 |
| 적기 | FAB → 제목만 입력. 갈래 하나 + 필요하면 `＋ 같이` 토글 |

## 6. 달력 칸 읽는 법

| 표시 | 뜻 |
|------|-----|
| 막대 길이 8 / 14 / 20px | 1–2개 / 3–4개 / 5개 이상 |
| 첫째 줄 | 나 (보는 사람) |
| 둘째 줄 | 상대 |
| 셋째 줄 (빨강) | 업무 |
| **빨강이 길면** | 일에 잡아먹힌 날 — 약속 잡기 전에 먼저 보이는 신호 |
| **빨강이 없으면** | 둘 다 여유 있는 날 |
| 회색 막대 | 다 끝냈거나 지나간 날 — 신경 쓸 필요 없음 |
| 아무것도 없음 | 비어 있는 날. 채우라는 표시는 뜨지 않음 |

## 7. 압박을 만들지 않기 위한 규칙

| 상황 | 흔한 앱 | 여기서는 |
|------|---------|----------|
| 할 일 적을 때 | 날짜·시각·소요시간·우선순위를 묻는다 | **제목만.** 갈래 하나 누르고 끝 |
| 어제 못 끝냈을 때 | 빨간 "지연"이 쌓인다 | 맨 위 한 줄 + `옮기기 / 나중에` |
| 순서 정하고 싶을 때 | 시:분을 지정하게 한다 | 시간 개념이 **아예 없다** |
| 상대가 안 했을 때 | "콕 찌르기", 독촉 알림 | **재촉 기능을 넣지 않는다** |
| 상대 할 일을 대신 지우고 싶을 때 | 같이 쓰니 누구나 수정 | 상대 갈래는 **읽기 전용.** 적으면 **제안**으로 |
| 언제 할지 모를 때 | 일단 오늘 날짜가 붙는다 | **"언젠가"** 서랍. 알림도 독촉도 없음 |
| 다 못 한 하루의 끝 | 달성률 20% | 퍼센트를 쓰지 않는다. **개수로만** |
| 연속 기록 | 스트릭이 끊기면 불이 꺼진다 | 스트릭 기능 자체를 **넣지 않는다** |

## 8. 디자인 토큰

**같은 색을 두 벌로 쓴다.** 밝은 값은 막대·체크 같은 *표시*에, 짙은 `-ink` 값은 *글자*에.
밝은 하늘색을 그대로 글자에 쓰면 흰 배경에서 읽히지 않는다.

| 토큰 | 라이트 | 다크 | 용도 |
|------|--------|------|------|
| `hyein` | `#A281EE` 라일락 | `#B79BF7` | 혜인 — 막대·체크 |
| `hyein-ink` | `#6B3FC4` | `#C9B4FB` | 혜인 — 글자 |
| `minwoo` | `#3E9DE8` 스카이 | `#5FB5F5` | 민우 — 막대·체크 |
| `minwoo-ink` | `#16639F` | `#8CCBFA` | 민우 — 글자 |
| `work` | `#F5503C` 버밀리언 | `#FF7A66` | 업무 — 막대·체크 |
| `work-ink` | `#C0301F` | `#FF9E8D` | 업무 — 글자 |
| `ink` | `#1E2A4A` 딥인디고 | `#E6EDFB` | 글자 · 오늘 |
| `paper` | `#E2EDFA` 연한 스카이 | `#0A0F1C` | 바탕 |
| `surface` | `#FFFFFF` | `#141B2E` | 카드 · 본문 면 |
| `faint` | `#A9B4CF` | `#5A6584` | 흐림 · 완료 |

- 달력 패널에는 **스카이 → 라일락 → 흰색** 그라데이션 (보는 사람에 따라 순서가 바뀜)
- **글자**: 한 가지 산세리프, 굵기로만 구분. 고정폭(모노) 숫자 없음. 달력 숫자만 `tabular-nums`
- **형태**: 격자선 대신 옅은 면과 여백. 모서리 10–12px, 막대는 완전히 둥글게
- **접근성**: 라일락과 스카이는 같은 한색 계열이라 갈래 순서를 어디서나 고정.
  빨강은 명도까지 달라 흑백에서도 구분된다. 대비 4.5:1 이상 / 터치 44px 이상

## 9. 화면이 좁아지면

| 폭 | 달력 | 할 일 |
|----|------|-------|
| ≥1280 | 왼쪽 고정 패널 · 한 달 전체 | 나 · 상대 · 업무 3단 |
| 1000–1279 | 왼쪽 고정 · 패널 폭만 축소 | 3단 유지 (카드 폭 축소) |
| 700–999 | 왼쪽 고정 · 한 달 전체 | 나·상대 2단 + 업무 아래 전체 폭 |
| <700 | 상단 고정 · 스크롤 시 그 주 한 줄로 축소 | 한 줄 목록 + 갈래 칩 필터 |

## 10. 결정이 필요한 항목

1. **업무 갈래를 서로 볼 수 있는지** — 지금은 둘 다 쓰되 아바타가 붙고 기본은 `내 것만`.
   아예 서로 안 보이게 하거나, 반대로 전부 공개할 수도 있다
2. **"제안" 기능이 필요한지** — 상대 갈래에 적으면 제안으로 전달되고 상대가 받아야 들어간다.
   그냥 못 적게 막는 게 단순할 수도 있다
3. **알림** — 재촉 알림은 없다. 다만 *"민우가 8/12 출장을 추가했어요"* 같은
   **변경 알림**은 필요한지
4. **연결 방식** — 초대 링크 하나로 묶는 방식을 상정했다. 계정을 따로 만들지 않고
   링크만으로 되게 할지
5. **다음 단계** — ① 클릭 가능한 프로토타입 ② 프론트엔드 골격 구현 ③ 데이터 모델·동기화 설계
