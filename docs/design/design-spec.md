# 하루 — 화면 설계서 v2.0

캘린더가 늘 곁에 있는, **혜인과 민우가 같이 쓰는** 네 갈래 to-do 서비스. 웹과 앱 모두 지원.

**구현되었습니다.** 실행 방법과 코드 구조는 [루트 README](../../README.md) 참고.
이 문서는 무엇을 왜 그렇게 정했는지를 남긴 기록이다.

**시각 자료: [`screens.html`](./screens.html)** — 실제로 돌아가는 앱을 찍은 스크린샷과
색 체계가 들어 있다. 브라우저로 바로 열 수 있다.

---

## 0. 네 갈래

갈래는 **두 축**이 만나 넷이 된다 — `누구 것인가(나/상대) × 어떤 일인가(개인/업무)`.

| 갈래 | 표시 색 | 글자 색 | 내용 |
|------|---------|---------|------|
| **혜인** | `#B49BF5` 연보라 | `#7B5AD6` | 혜인의 개인 일정 |
| **혜인 업무** | `#7C3AED` 진보라 | `#5B21B6` | 혜인의 회사 일 |
| **민우** | `#7FC8F5` 하늘 | `#17699F` | 민우의 개인 일정 |
| **민우 업무** | `#1D6FD4` 진파랑 | `#114E96` | 민우의 회사 일 |

각자 자기 두 갈래를 직접 적고 체크한다. **상대의 두 갈래는 볼 수만 있다.**

### 왜 두 축인가

갈래가 넷인데 색을 넷 다 따로 고르면 무지개가 되고, 무엇이 무엇인지 외워야 한다.

- **계열 = 사람** — 혜인은 보라, 민우는 파랑. 색이 먼저 눈에 들어오므로
  "누구 것인가"가 먼저 읽힌다
- **단계 = 개인/업무** — 개인은 연하고 부드럽게, 업무는 진하고 선명하게.
  명도와 채도를 동시에 움직여 간격을 크게 벌렸다. 일이 낀 날이 달력에서 무겁게 보인다

**색이 주된 신호다.** 갈래 머리글에 바탕을 깔고 **할 일 카드마다 왼쪽에 색 띠**를 넣어,
목록을 훑는 동안에도 색이 계속 보인다.

- **모양은 보조 신호** — 둥글면 개인, 각지면 업무. 체크박스·카드 모서리·갈래 표식·달력 막대가
  전부 같은 규칙을 따른다

> 처음에는 모양만으로 나눠 봤는데 *눈에 잘 들어오지 않았다.* 색 간격을 벌리고 면적을 넓힌
> 다음에야 모양이 제 역할을 한다 — 주된 신호가 아니라 거들어 주는 역할일 때 작동한다.
> 덤으로 흑백으로 인쇄해도 구분된다.

> **경고용 빨강은 갈래에서 빠졌다.** 지금 빨강 계열(`--alert`)은 "연결이 끊겼다" 같은
> 시스템 오류에만 쓰이고, 할 일에는 절대 붙지 않는다.

> 어두운 화면에서는 "진하다"가 곧 "안 보인다"가 된다. 그래서 다크 모드에서는
> 축을 뒤집지 않고 바꾼다 — 개인은 연하고 흐릿하게, 업무는 채도를 올려 선명하게.

## 1. 공유 규칙

같이 쓰는 앱이 어려워지는 건 대개 "누가 뭘 할 수 있는지"가 흐릿해서다. 규칙은 셋뿐이다.

1. **체크는 자기 것만** — 상대 갈래 항목은 체크박스가 아예 나타나지 않고 **작은 점**으로 보인다.
   흐린 체크박스는 "지금은 안 되지만 언젠가 될 것"처럼 보이므로, 아예 다른 모양으로 바꾼다.
2. **같이 하는 일은 두 칸에 모두** — `같이` 배지가 붙은 항목은 누가 적었든
   **혜인 개인 칸과 민우 개인 칸 양쪽에** 나온다. 달력 막대도 둘 다 그린다.
   한 칸에만 두면 나머지 칸이 비어서 "저 사람은 이걸 안 하나"처럼 보인다.
   손대는 곳은 하나다 — 내 칸의 것만 체크할 수 있고, 상대 칸에 비친 것은 점으로만 보인다.
   한 명이 체크하면 양쪽에서 완료된다.
   (고치고 지우는 건 적은 사람만 — 항목이 하나뿐이므로 주인이 분명해야 한다.)
3. **자리는 보는 사람 기준, 색은 사람 기준** — 민우가 열면 왼쪽 그룹이 **민우**가 된다.
   언제나 `내 개인 → 내 업무 → 상대 개인 → 상대 업무` 순서.
   그러나 **색은 따라 뒤집히지 않는다.** 먼저 온 사람이 보라, 나중에 온 사람이 파랑으로
   고정이라 혜인은 어느 화면에서나 보라고 민우는 어느 화면에서나 파랑이다.
   색까지 화면마다 뒤집히면 "이 보라가 누구였더라"를 매번 다시 읽어야 한다.

**상대 갈래에는 추가 입력이 아예 없다.** 각자 자기 갈래만 쓰므로 "제안" 같은 중간 단계가
필요하지 않다 — 민우 일정은 민우가 직접 적고, 혜인은 그것을 참고용으로 본다.

상대 갈래 항목은 내 "남은 개수"에도 들어가지 않는다. 그래서 개수 표기가
`n 남음`이 아니라 **`n 건`** 이다.

## 2. 문제 정의와 방향

- 캘린더 앱의 **시간 격자**는 "몇 시에 무엇을 할지" 정하라고 요구해 부담이 된다
- 하지만 **한 달의 흐름**은 계속 보고 싶다

→ 화면을 `왼쪽 = 달력(읽기용) / 오른쪽 = 할 일(작업용)`로 나눈다.
달력은 일정을 적는 곳이 아니라 **지금 어디쯤 와 있는지 보는 지도**다.

## 3. 설계 원칙

| # | 원칙 | 의미 |
|---|------|------|
| 1 | **시간이 아예 없다** | 시각도, 아침·낮·저녁 같은 구간도 없다. 데이터 모델에 필드 자체가 없다 |
| 2 | **달력은 읽는 곳** | 칸 안에 글자를 넣지 않는다. 얇은 막대 네 줄로 그날의 *양*만 표시 |
| 3 | **못 한 건 그냥 넘어간다** | 빨간 "지연" 배지 없음. 어제 남은 항목은 맨 위에 조용히 모아 `오늘로 옮기기` |
| 4 | **재촉하지 않는다** | 상대가 안 한 일에 대한 알림이 없다. **독촉 버튼도, 콕 찌르기도 없다** |

## 4. 정보 구조

### 웹 — 2단
- **왼쪽 (320px 고정)** — 월간 달력 · 범례 · 오늘로 돌아가기. **어느 화면에서도 그대로**
- **오른쪽** — `하루` / `이번 주` / `언젠가` 세 가지 중 하나 + `우리`(설정)

### 모바일
달력은 **상단 고정 영역**이다. 스크롤해도 사라지지 않고, 접으면 그 주 한 줄로 줄어들 뿐이다.

### 데이터 모델

```
Space {                              // 혜인 + 민우가 공유하는 하나의 공간
  id, name, inviteCode
  version                            // 쓰기마다 +1 — 화면이 이 숫자만 보고 다시 부른다
}

Todo {
  id
  lane      : 'personal' | 'work'    // 사람 이름이 아니라 의미로 저장한다
  ownerId                            // 이 항목을 적고 체크할 수 있는 사람
  together  : bool                   // true 면 둘 다 체크 가능, 한 번 체크로 양쪽 완료
  title                              // 필수 — 이것만 있으면 저장됨
  date?                              // 없으면 "언젠가" 서랍
  endDate?                           // 여러 날 항목 (출장 등)
  position                           // 같은 날 안에서의 순서
  done, doneAt?, doneBy?
  carriedFrom?                       // 이월 표시 "어제에서"
  note?, subtasks[], repeat?
}
```

화면에 보이는 `혜인 / 혜인 업무 / 민우 / 민우 업무` 는 저장된 값이 아니라
**보는 사람 기준으로 계산된 자리**다. 색은 이 자리가 아니라 사람에게 붙는다 —
공간을 만든 사람이 자리 a(보라), 나중에 들어온 사람이 자리 b(파랑)이고,
b 인 사람의 화면에서는 자리와 색의 연결만 뒤집는다.

```
lane 'personal' + owner === 나      → bucket 'mine'
lane 'work'     + owner === 나      → bucket 'mineWork'
lane 'personal' + owner === 상대    → bucket 'partner'
lane 'work'     + owner === 상대    → bucket 'partnerWork'
```

이 계산 하나로 누가 로그인하든 같은 코드가 돌고, 각자에게 자기 갈래가 먼저 온다.
서버는 항목마다 `canCheck` / `canEdit` / `countable` 을 함께 내려주므로
**화면은 권한을 다시 판단하지 않는다** — 규칙이 한 곳에만 있다.

시각(`time`), 시간 구간(`part`), 소요시간(`estimate`), 우선순위(`priority`),
지연(`overdue`) 필드는 **의도적으로 없다.**

## 5. 화면별 사양

### S1. 하루 (웹)

**왼쪽 달력 패널**
- 6주 × 7일, 칸 높이 60px, 칸 안은 **날짜 숫자 + 얇은 막대 네 줄**뿐
- 막대 순서 위→아래: **내 개인 · 내 업무 · 상대 개인 · 상대 업무**
- 상단에 두 사람 아바타 — 지금 누구와 같이 쓰는지 항상 보임
- 오늘 = 짙은 채움, 선택한 날 = 얇은 테두리, 일요일 = 바이올렛 숫자

**오른쪽 본문**
- 이월 안내: "어제까지 못 한 일이 2개 있어요" → `오늘로 옮기기`
- **사람으로 먼저 2단**(나 / 상대), 각 그룹 안에서 **개인 · 업무 2단**
  - 사람 그룹 머리글은 그 사람 색 2px 밑줄
  - 상대 그룹에 `보기만` 배지
- 완료 항목은 접히고, 배경 없이 취소선 + 흐린 글자로만 남음

> 갈래 넷을 평평하게 늘어놓으면 매번 이름을 읽어야 한다.
> 사람으로 묶어 두면 "내 칸"을 먼저 찾고 그 안을 훑게 된다.

### S2. 이번 주 (웹)

- **달력 패널은 그대로.** 선택한 주가 달력에서 옅은 배경으로 표시됨
- 오른쪽만 7개 컬럼 — **시간축 없음, 그냥 목록 7개**
- 여러 날 항목은 걸쳐 있는 모든 날 칸에 나타난다

### S3. 모바일

| 화면 | 구성 |
|------|------|
| 기본 | 상단 고정 달력 + 아래 목록. **내 것 → 상대 것** 순 |
| 사람 필터 | `둘 다 · 나 · 상대` 칩 |
| 상대 화면 | 같은 데이터인데 **자기 갈래가 먼저** 온다. 달력 막대 순서도 뒤집힘 |
| 달력 접기 | 위로 쓸어올리면 그 주 **한 줄**로 축소. 완전히 사라지지 않음 |

## 6. 달력 칸 읽는 법

| 표시 | 뜻 |
|------|-----|
| 막대 길이 8 / 14 / 20px | 1–2개 / 3–4개 / 5개 이상 |
| 첫째 줄 (연한 색, 둥근 끝) | 내 개인 |
| 둘째 줄 (진한 색, 각진 끝) | 내 업무 |
| 셋째 줄 (연한 색, 둥근 끝) | 상대 개인 |
| 넷째 줄 (진한 색, 각진 끝) | 상대 업무 |
| **진한 막대가 길면** | 일에 잡아먹힌 날 — 약속 잡기 전에 먼저 보이는 신호 |
| 회색 막대 | 다 끝냈거나 지나간 날 — 신경 쓸 필요 없음 |
| 아무것도 없음 | 비어 있는 날. 채우라는 표시는 뜨지 않음 |

## 7. 압박을 만들지 않기 위한 규칙

| 상황 | 흔한 앱 | 여기서는 |
|------|---------|----------|
| 할 일 적을 때 | 날짜·시각·소요시간·우선순위를 묻는다 | **제목만.** 날짜도 선택 |
| 순서 정하고 싶을 때 | 시:분을 지정하게 한다 | 시간 개념이 **데이터에 아예 없다** |
| 어제 못 끝냈을 때 | 빨간 "지연"이 쌓인다 | 맨 위 한 줄 + `오늘로 옮기기` |
| 상대가 안 했을 때 | "콕 찌르기", 독촉 알림 | **재촉 기능을 넣지 않았다** |
| 상대 할 일을 고치고 싶을 때 | 같이 쓰니 누구나 수정 | 상대 갈래는 **읽기 전용.** 추가 입력 자체가 없다 |
| 둘 다 해야 하는 일 | 두 번 적는다 | **`같이`** 배지 — 양쪽 자기 칸에 뜨고, 한 명이 체크하면 양쪽에서 끝 |
| 언제 할지 모를 때 | 일단 오늘 날짜가 붙는다 | **`언젠가`** 서랍. 알림도 독촉도 없음 |
| 다 못 한 하루의 끝 | 달성률 20% | 퍼센트를 쓰지 않는다. **개수로만** |
| 연속 기록 | 스트릭이 끊기면 불이 꺼진다 | 스트릭 기능 자체가 **없다** |

## 8. 디자인 토큰

**같은 색을 두 벌로 쓴다.** 기본 값은 막대·체크 같은 *표시*에, 짙은 `-ink` 값은 *글자*에.
연한 색을 그대로 글자에 쓰면 흰 배경에서 읽히지 않는다.

| 토큰 | 라이트 | 다크 | 용도 |
|------|--------|------|------|
| `mine` | `#B49BF5` | `#C9B4FB` | 내 개인 — 표시 |
| `mine-ink` | `#7B5AD6` | `#D5C4FC` | 내 개인 — 글자 |
| `mineWork` | `#7C3AED` | `#9F6BFF` | 내 업무 — 표시 |
| `mineWork-ink` | `#5B21B6` | `#BE9BFF` | 내 업무 — 글자 |
| `partner` | `#7FC8F5` | `#A8D8FA` | 상대 개인 — 표시 |
| `partner-ink` | `#17699F` | `#BEE3FB` | 상대 개인 — 글자 |
| `partnerWork` | `#1D6FD4` | `#4D9BF0` | 상대 업무 — 표시 |
| `partnerWork-ink` | `#114E96` | `#7FBFF5` | 상대 업무 — 글자 |
| `alert` | `#B03A54` | `#F2A3B4` | **시스템 오류 전용.** 할 일에는 안 쓰임 |
| `ink` | `#1E2A4A` 딥인디고 | `#E6EDFB` | 글자 · 오늘 |
| `paper` | `#E6EEFA` | `#0A0F1C` | 바탕 |
| `surface` | `#FFFFFF` | `#141B2E` | 카드 · 본문 면 |
| `faint` | `#A9B4CF` | `#5A6584` | 흐림 · 완료 |

- 달력 패널에는 **상대 색 → 내 색 → 흰색** 그라데이션 (보는 사람에 따라 순서가 바뀜)
- **글자**: 한 가지 산세리프, 굵기로만 구분. 고정폭(모노) 숫자 없음. 달력 숫자만 `tabular-nums`
- **형태**: 격자선 대신 옅은 면과 여백. 카드마다 왼쪽 3px 색 띠.
  개인은 둥근 모서리(6–10px), 업무는 각진 모서리(2–4px)
- **접근성**: 색이 안 보여도 **모양과 자리(순서 고정)**로 구분된다.
  본문 대비 4.5:1 이상 / 터치 44px 이상

## 9. 화면이 좁아지면

달력은 어느 크기에서도 화면에서 빠지지 않는다.

| 폭 | 달력 | 할 일 |
|----|------|-------|
| ≥1000 | 왼쪽 고정 패널 · 한 달 전체 | 사람 2단 × 각 개인·업무 2단 |
| 700–999 | 왼쪽 고정 · 한 달 전체 | 사람을 위아래로, 개인·업무는 나란히 |
| <700 | 상단 고정 · 접으면 그 주 한 줄 | 전부 한 줄씩 + 사람 칩 필터 |

## 10. 어떻게 돌아가나

```
브라우저 · 홈 화면 앱  →  Vercel  →  Turso
        (화면)          (판단)     (보관)
```

- **Vercel** — 로그인 확인, 권한 판단, 조회·저장 실행. **데이터는 들고 있지 않다**
- **Turso** — 계정·공간·할 일이 전부 여기. SQLite 그대로라 통째로 내려받아 옮길 수 있다
- **실시간 반영** — 8초마다 `{"version":37}` 만 확인하고 바뀌었을 때만 전체를 부른다.
  화면을 보고 있지 않으면 아예 묻지 않는다
- **비밀번호** — scrypt 해시만 저장. 원본은 어디에도 없다

로컬 개발과 테스트는 Node 내장 `node:sqlite` 로 의존성 없이 오프라인에서 돈다.
같은 인터페이스 뒤에 백엔드가 둘 있고, 환경변수 하나로 갈린다.

## 11. 남은 논의

1. **상대 업무를 봐도 되나?** 지금은 보인다(읽기 전용). 서로의 업무까지 보는 게 부담이면
   *업무는 각자만 보기*로 되돌릴 수 있다 — 규칙 한 줄이다
2. **변경 알림** — 재촉 알림은 없다. 다만 *"민우가 8/12 출장을 추가했어요"* 같은
   **변경 알림**은 필요한지
3. **반복 일정** — 스키마에 `repeat` 자리는 있지만 아직 화면이 없다
4. **순서 끌어 옮기기** — API(`POST /api/todos/reorder`)는 있고 드래그 조작은 아직 없다
