# 인수인계 — "하루"에서 상업 서비스로

이 문서는 **다른 대화 창에서 처음부터 시작하는 사람(또는 AI)** 이 읽는 것이다.
앞선 대화의 기억은 창을 넘어가지 않으므로, 넘겨야 할 것을 여기 적어 둔다.

새 대화를 열면 **이 문서 전체를 첫 메시지로 붙여넣으면 된다.**

---

## 0. 한 줄 요약

`하루`는 **커플 둘이 서로의 할 일을 보며 쓰는 to-do 앱**이다.
개인용으로 완성해 실제로 쓰고 있고(`hyenn529/to-dos`), 이제 **같은 컨셉으로 상업 서비스**를
**완전히 별개의 레포·별개의 DB**에서 새로 만든다.

> **데이터는 절대 섞지 않는다.** 기존 앱에는 실제 개인 일정이 들어 있다.
> 새 프로젝트는 DB·배포·레포가 전부 따로다.

---

## 1. 이 제품이 무엇인가

**둘만 쓰는 to-do.** 세 명 이상은 받지 않는다. 그 좁음이 이 앱이 편한 이유다.

- 한 사람이 공간을 만들고, **초대 코드 하나**로 상대를 부른다. 그걸로 끝이다
- 각자 `개인` / `업무` 두 갈래를 갖는다 → 화면에는 **네 칸**이 보인다
- **상대 칸은 보기만 한다.** 체크도 수정도 안 된다
- 「같이」 붙인 일만 예외 — 두 사람 칸에 모두 뜨고, 한 명이 체크하면 양쪽에서 끝난다
- **월간 달력이 화면에서 사라지지 않는다.** 이게 1번 요구사항이었다

---

## 2. 절대 규칙 — 이걸 어기면 다른 제품이 된다

사용자가 명시적으로 거부한 것들이다. 편의를 이유로 되살리지 말 것.

| 넣지 않는다 | 이유 (사용자의 말) |
|---|---|
| **시간표·시간 격자** | "너무 시간 단위 관리처럼 느껴져서 부담스러워" |
| **아침/낮/저녁 구간** | 시간 개념을 완전히 지웠다 |
| **재촉·콕 찌르기 알림** | 상대를 압박하는 기능은 넣지 않는다 |
| **달성률 퍼센트** | 다 못 한 날 "20%"는 벌점처럼 읽힌다. **개수로만** |
| **연속 기록(스트릭)** | 끊기면 그만두게 된다 |
| **제안·승인 같은 중간 단계** | "제안? 뭐에 대한 제안인지 모르겠어" — 각자 자기 것만 쓴다 |

**색과 인상**: "매일 볼 앱이라 열었을 때 질리지 않고 상큼하거나 발랄했으면 좋겠어."
하늘색 + 연보라 계열. 채도 높은 경고색은 **시스템 오류에만** 쓰고 할 일에는 절대 쓰지 않는다.

---

## 3. 설계 결정과 그 이유

### 색은 사람에게 고정한다 (자리에 붙이지 않는다)
- 공간을 만든 사람 = 보라, 나중에 들어온 사람 = 파랑
- **누구 화면에서 보든 같다.** 처음엔 "내 것=보라"로 만들었더니 상대 화면에서 뒤집혀서
  "이 보라가 누구였더라"를 매번 다시 읽어야 했다
- 자리 배치(내 칸이 왼쪽)만 보는 사람 기준으로 남긴다

### 갈래는 색이 먼저, 모양이 보조
- 사람 = 색 계열, 개인/업무 = 그 계열 안의 진하기
- 개인은 둥글게, 업무는 각지게 — **모양만으로는 안 읽힌다**는 걸 실제로 확인했다
  ("모양은 잘 안들어와") → 색이 신호를 지고, 모양은 거들기만 한다
- 색 면적이 충분해야 한다. 얇은 띠로는 부족해서 머리글 바탕까지 칠했다

### 못 누르는 것은 흐리게 하지 않는다
- 상대의 할 일은 **흐린 체크박스가 아니라 점(dot)** 으로 그린다
- 흐린 체크박스는 "지금은 안 되지만 언젠가 될 것"처럼 보인다

### 「같이」는 두 칸에 모두
- 한 칸에만 두면 나머지 칸이 비어서 "저 사람은 이걸 안 하나"처럼 보인다
- 다만 **손대는 곳은 하나**다 — 내 칸의 것만 체크되고, 상대 칸에 비친 것은 점이다

### 「언젠가」 서랍
- 날짜 없는 할 일을 두는 곳. 알림도 독촉도 없다
- 날짜를 강제로 붙이면 "오늘 못 했다"가 매일 쌓인다

### 지난 일은 배지가 아니라 한 줄
- "어제까지 못 한 일이 N개 있어요" + `오늘로 옮기기` 버튼 하나
- 빨간 숫자가 쌓이는 UI를 만들지 않는다

## 4. 지금 구현 (참고용 — 그대로 가져가지 말 것)

`hyenn529/to-dos` 에 있다. **컨셉만 가져가고 구조는 새로 짠다.**
이유: "2인"이 뼈대에 박혀 있어서 그대로 쓰면 그 한계도 같이 온다.

- 서버: Node 22 + Express 5 (`.ts` 를 빌드 없이 실행 — 타입 스트리핑)
- DB: SQLite. 로컬은 내장 `node:sqlite`, 배포는 Turso(`@libsql/client/web`)
- 웹: React 19 + Vite + CSS 변수 토큰 (밝게/어둡게)
- 앱: PWA (홈 화면에 추가). 스토어 등록은 안 했다
- 배포: Vercel (서버리스 함수 하나 + 정적 파일)
- 동기화: 8초마다 **버전 번호만** 물어보고 바뀌었을 때만 다시 불러온다
  (서버리스는 연결을 붙들 수 없어 SSE를 포기했다)

**2인 전제가 박혀 있는 곳** — 새로 짤 때 여기가 다 바뀐다:
- `findPartner` 가 상대를 **한 명만** 찾는다
- 자리가 `a`/`b` 둘뿐이라 색도 둘뿐이다
- 화면이 `내 개인 / 내 업무 / 상대 개인 / 상대 업무` 네 칸 고정이다

## 5. 배포에서 실제로 겪은 함정 (같은 데서 또 막히지 말 것)

| 증상 | 원인 |
|---|---|
| 빌드가 계속 실패 | Vercel **Root Directory** 가 하위 폴더로 잡혀 루트 `vercel.json` 을 아예 안 읽었다 |
| `EBADENGINE` | `engines` 로 Node 버전을 못 박으면 더 높은 Node 를 쓰는 환경에서 거절당한다. 적지 않는다 |
| 함수가 500만 뱉음 | Vercel 은 타입만 벗기고 **번들하지 않는다.** esbuild 로 미리 묶어야 한다 |
| `functions` 패턴 거절 | 빌드 **전에** 검사하므로 생성될 파일은 커밋해 둬야 한다 |
| `Invalid URL` / `invalid header value` | 환경변수 붙여넣기에 **공백·줄바꿈**이 섞였다. 코드가 다듬게 한다 |
| `SQL not allowed statement: PRAGMA user_version` | Turso 는 PRAGMA 쓰기를 막는다. 마이그레이션 기록은 **평범한 표**에 남긴다 |
| 원인을 알 수 없는 500 | 모듈 로드 시점에 DB 연결하면 설정 오류에 함수가 통째로 죽는다. **첫 요청 때** 연결한다 |

## 6. 상업화에서 반드시 달라지는 것

### 구조
- **2인 고정 → 다수 사용자.** 데이터 모델부터 다시. 단, 제품은 여전히 "둘이 쓰는 앱"으로 판다
- 공간(space)이 여러 개, 사용자도 여러 공간에 속할 수 있는지 먼저 정할 것

### 남에게 열기 전 최소선 (지금 앱에는 전부 없다)
- 로그인 시도 제한 (지금은 비밀번호 무한 대입 가능)
- 이메일 인증
- 비밀번호 재설정
- 회원 탈퇴 · 데이터 삭제 (법적 의무)
- 개인정보처리방침 · 이용약관 (**구글 등록 필수 요건**)
- 백업

### 비용
- **Vercel 무료(Hobby)는 상업적 이용 금지.** 결제·광고를 붙이면 Pro 로 올려야 한다
- Turso 무료 한도는 사용자 수십 명이면 찬다

### 스토어
- PWA 를 TWA 로 감싸면 Play 스토어에 올라간다
- 개발자 계정 $25(1회), 개인정보처리방침 URL 필수
- **개인 계정은 테스터 12명이 14일 연속 테스트**해야 출시된다
